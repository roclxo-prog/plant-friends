# 검색엔진 등록 가이드 — 우리집 초록친구

이 문서는 "우리집 초록친구" 사이트를 구글·네이버·빙 등 검색엔진에 등록하고, 시니어(50대 이후) 사용자가 자주 쓰는 검색어로 잘 노출되도록 만드는 단계별 안내서입니다.
처음 하시는 분도 따라 하실 수 있게 메뉴 경로와 버튼 이름까지 적어 두었습니다. 천천히 한 단계씩 진행해 주세요.

> 우리 사이트의 주요 사용자는 시니어 세대입니다. 시니어 분들은 **네이버**를 가장 많이 쓰시므로, 시간이 부족하시면 **네이버 서치어드바이저 등록을 가장 먼저** 끝내 주세요.

---

## 0. 시작 전 준비 (가장 중요)

배포된 파일에는 임시 주소인 `https://example.pages.dev` 가 들어 있습니다. 검색엔진에 등록하기 **전에** 반드시 실제 도메인으로 바꿔 주세요. 이 작업을 건너뛰면 검색엔진이 존재하지 않는 주소를 색인하여, 등록을 다시 해야 합니다.

### 0-1. URL 치환 대상 (배포 전 일괄 변경)

`https://example.pages.dev` 를 실제 도메인(예: `https://초록친구.example.pages.dev` 또는 구입하신 도메인)으로 바꿔야 하는 파일:

| 파일 | 바꿀 위치 |
|---|---|
| `scripts/config.js` | `SITE_URL` 값 (여기가 원본 기준값) |
| `sitemap.xml` | 모든 `<loc>` 의 origin 부분 |
| `robots.txt` | `Sitemap:` 줄의 주소 |
| `*.html`, `plants/*.html` | 각 페이지의 JSON-LD(`@id`, `url`), canonical, og:url |

권장 순서: 먼저 `scripts/config.js` 의 `SITE_URL` 을 실제 도메인으로 고치고, 그 값을 기준으로 나머지 파일의 `https://example.pages.dev` 를 동일하게 일괄 치환합니다.

### 0-2. 치환 확인

치환 후 사이트 전체에 `example.pages.dev` 가 한 군데도 남지 않았는지 검색해 확인해 주세요. 한 곳이라도 남아 있으면 그 페이지는 색인이 잘못됩니다.

확인용 명령(프로젝트 폴더에서):

```powershell
Select-String -Path .\sitemap.xml,.\robots.txt -Pattern "example.pages.dev"
Get-ChildItem -Recurse -Include *.html | Select-String -Pattern "example.pages.dev"
```

결과가 아무것도 나오지 않으면 치환 완료입니다.

### 0-3. 배포 후 접속 확인

배포한 뒤 브라우저에서 아래 두 주소가 정상적으로 열리는지 먼저 확인해 주세요. (`(실제도메인)` 자리에 본인 주소를 넣습니다.)

- `https://(실제도메인)/sitemap.xml` → XML 목록이 보이면 정상
- `https://(실제도메인)/robots.txt` → 텍스트가 보이고 `Sitemap:` 줄에 실제 도메인이 들어 있으면 정상

이 두 가지가 잘 열려야 다음 단계에서 검색엔진에 제출할 수 있습니다.

## 1. 구글 Search Console 등록

구글 검색에 노출되기 위한 필수 단계입니다.

### 1-1. 접속 및 속성(사이트) 추가

1. `https://search.google.com/search-console` 에 접속하여 구글 계정으로 로그인합니다.
2. 왼쪽 위 속성 선택 메뉴에서 **[속성 추가]** 를 누릅니다.
3. 등록 방식 두 가지 중 하나를 고릅니다.

| 방식 | 입력 예 | 장점 | 소유권 확인 방법 |
|---|---|---|---|
| **도메인** | `초록친구.example.dev` 처럼 도메인 전체 | http/https, www 유무, 하위 경로 모두 한 번에 포함 | **DNS** 레코드만 가능 |
| **URL 접두어** | `https://(실제도메인)/` 처럼 주소 전체 | DNS를 못 만져도 HTML 태그 등으로 간편 확인 | HTML 태그/파일, GA, GTM 등 여러 방법 |

> DNS 설정에 접근할 수 있으면 **도메인 방식**을 권장합니다. 도메인을 직접 관리하기 어렵거나 `*.pages.dev` 하위 도메인을 쓰신다면 **URL 접두어 방식**이 더 쉽습니다.

### 1-2. 소유권 확인 — 방법 A: HTML 태그 (URL 접두어 방식 권장)

1. URL 접두어 방식 선택 후 확인 화면에서 **[HTML 태그]** 를 펼칩니다.
2. 아래와 같은 메타 태그가 나옵니다. 복사합니다.

   ```html
   <meta name="google-site-verification" content="여기에_고유코드" />
   ```

3. 사이트의 **모든 페이지 공통 `<head>`** 에 붙여 넣습니다. 우리 사이트는 페이지마다 HTML이 나뉘어 있으므로, 최소한 메인 `index.html` 의 `<head>` 안(`</head>` 바로 위)에 추가하고 재배포합니다.
4. 배포가 끝난 뒤 Search Console로 돌아와 **[확인]** 을 누릅니다.

### 1-3. 소유권 확인 — 방법 B: DNS (도메인 방식)

1. 도메인 방식 선택 시 안내되는 **TXT 레코드 값**을 복사합니다. (예: `google-site-verification=xxxxxxxx`)
2. 도메인을 구입한 곳(또는 Cloudflare 등 DNS 관리 콘솔)에서 DNS 레코드를 추가합니다.
   - 유형: `TXT`
   - 이름/호스트: `@` (루트)
   - 값: 복사한 `google-site-verification=...` 전체
3. 저장 후 Search Console에서 **[확인]** 을 누릅니다. DNS 반영에 수 분~수 시간이 걸릴 수 있으니, 바로 안 되면 잠시 후 다시 시도합니다.

### 1-4. sitemap.xml 제출

1. 왼쪽 메뉴 **[색인] → [Sitemaps]** 로 들어갑니다.
2. "새 사이트맵 추가" 칸에 `sitemap.xml` 만 입력합니다. (앞의 도메인은 이미 채워져 있습니다.)
3. **[제출]** 을 누릅니다. 잠시 후 상태가 **"성공"** 으로 바뀌면 정상입니다.

### 1-5. 색인(등록) 요청

새 사이트나 새 페이지는 색인을 앞당기기 위해 직접 요청할 수 있습니다.

1. 화면 맨 위 **URL 검사** 칸에 점검할 주소를 붙여 넣습니다. (예: `https://(실제도메인)/guide.html`)
2. 결과 화면에서 **[색인 생성 요청]** 을 누릅니다.
3. 우선순위가 높은 아래 페이지부터 요청해 주세요. (한 번에 요청 가능한 수에 일일 한도가 있으니 중요한 순서로 나눠서 진행)
   - 메인 `/`
   - 케어가이드 허브 `/guide.html`
   - 추천 도구 `/quiz.html`
   - 식물 상세 12개 페이지 (`/plants/...`)

## 2. 네이버 서치어드바이저 등록 (시니어 주 사용 검색엔진 — 최우선)

시니어 사용자는 네이버 검색을 가장 많이 사용합니다. 이 단계를 가장 정성껏 진행해 주세요.

### 2-1. 사이트 등록

1. `https://searchadvisor.naver.com` 에 접속해 네이버 계정으로 로그인합니다.
2. 오른쪽 위 **[웹마스터 도구]** 로 들어갑니다.
3. 가운데 입력칸에 사이트 주소 `https://(실제도메인)/` 를 입력하고 **[+]** (추가) 버튼을 누릅니다.

### 2-2. 소유 확인

1. 등록 직후 **사이트 소유확인** 화면이 나옵니다. 두 방법 중 하나를 고릅니다.
   - **HTML 파일 업로드**: 안내된 인증 파일(예: `naverXXXX.html`)을 내려받아 사이트 **최상위 폴더**에 올리고 재배포합니다. `https://(실제도메인)/naverXXXX.html` 로 열리면 됩니다.
   - **HTML 태그**: 제공되는 `<meta name="naver-site-verification" content="..." />` 태그를 메인 `index.html` 의 `<head>` 안에 붙여 넣고 재배포합니다.
2. 업로드/배포가 끝나면 **[소유확인]** 버튼을 누릅니다.

### 2-3. 사이트맵 제출

1. 왼쪽 메뉴 **[요청] → [사이트맵 제출]** 로 들어갑니다.
2. 입력칸에 `sitemap.xml` 을 입력하고 **[확인]** 을 누릅니다. (도메인은 자동으로 붙습니다.)

### 2-4. robots.txt 확인 및 제출

1. **[검증] → [robots.txt]** 메뉴로 들어갑니다.
2. **[수집]** 을 눌러 현재 `robots.txt` 를 가져온 뒤, `Sitemap:` 줄이 실제 도메인으로 되어 있는지 확인합니다.
3. 문제가 없으면 그대로 두면 됩니다. (우리 `robots.txt` 는 전체 허용 설정이라 별도 차단은 없습니다.)

### 2-5. 웹페이지 수집(색인) 요청

1. **[요청] → [웹페이지 수집]** 으로 들어갑니다.
2. 색인을 원하는 페이지 주소를 한 줄씩 입력하고 **[확인]** 을 누릅니다. 1-5와 동일하게 메인 → 케어가이드 → 추천도구 → 식물 상세 순으로 진행합니다.

### 2-6. 웹마스터 도구 활용 (등록 후 꾸준히)

등록만 하고 끝내지 마시고, 주기적으로 아래 메뉴를 확인하면 노출이 좋아집니다.

- **[리포트] → [사이트 최적화]**: 제목/설명 중복, 이미지 alt 누락 등 개선점을 점검합니다. (우리 사이트는 title 60자·description 150자 이내 고유값을 지키고 있으니 경고가 없어야 정상)
- **[리포트] → [검색 노출/클릭 현황]**: 어떤 검색어로 들어오는지 확인하고, 5번의 키워드 전략을 다듬습니다.
- **[요청] → [웹페이지 수집]**: 식물 상세 페이지를 새로 추가했을 때 다시 요청합니다.

## 3. (선택) 빙 웹마스터 등록

빙(Bing)은 점유율은 낮지만, 구글 Search Console에서 한 번에 가져올 수 있어 손이 거의 가지 않습니다.

1. `https://www.bing.com/webmasters` 에 접속해 로그인합니다.
2. 시작 화면에서 **[Import from Google Search Console]** (Search Console에서 가져오기)를 선택합니다.
3. 구글 계정 연결을 허용하면, 1번에서 등록한 속성과 사이트맵이 자동으로 넘어옵니다.
4. 가져오기가 안 되거나 직접 등록을 원하면, 사이트 주소를 직접 추가하고 안내되는 **메타 태그 / XML 파일 / DNS** 중 하나로 소유 확인 후 `sitemap.xml` 을 제출합니다.

## 4. 시니어 검색어 롱테일 전략

시니어 사용자는 짧은 단어보다 **"OO 키우는 법", "OO 물주기", "OO 햇빛"** 처럼 풀어 쓴 문장형(롱테일) 검색어를 많이 씁니다. 이런 검색어는 경쟁이 덜하고, 우리 **케어가이드 페이지로 정확히 유입**시키기 좋습니다.

### 4-1. 핵심 방향

- 각 식물 상세 페이지는 그 식물의 **"키우는 법 / 물주기 / 햇빛"** 검색어를 정확히 노립니다.
- 케어가이드 허브(`/guide.html`)는 **"식물 키우는 법 모음", "공기정화 식물", "거실 식물 추천", "초보 식물"** 같은 묶음 검색어를 받아 상세 페이지로 연결합니다.
- 본문은 시니어가 실제로 묻는 문장("물은 며칠에 한 번 주나요?", "햇빛이 약한 거실에서도 키울 수 있나요?")에 답하듯 자연스럽게 씁니다.

> **키워드 스터핑 금지.** 같은 단어를 억지로 반복하지 마세요. 페이지당 **1차 키워드 1개 + 보조 키워드 2~4개**를 제목·소제목·본문에 자연스럽게 한 번씩 녹이는 정도가 가장 좋습니다. 반복이 많으면 오히려 순위가 내려갑니다.

## 5. 색인 점검

등록 후 검색엔진이 실제로 우리 페이지를 색인했는지 확인합니다. 보통 **며칠~2주** 정도 걸립니다.

### 5-1. site: 검색으로 빠르게 확인

구글/네이버 검색창에 아래처럼 입력하면 색인된 페이지 목록이 나옵니다.

```
site:(실제도메인)
```

- 결과가 나오면 색인이 시작된 것입니다.
- 특정 페이지만 확인하려면: `site:(실제도메인)/guide.html`

### 5-2. Search Console 커버리지(색인 현황) 확인

1. 구글 Search Console 왼쪽 **[색인] → [페이지]** 로 들어갑니다.
2. "색인이 생성됨" 페이지 수와 "색인이 생성되지 않음" 사유를 확인합니다.
3. 자주 보이는 사유와 대응:
   - **검색되었으나 아직 색인 생성되지 않음**: 정상적인 대기 상태입니다. 시간이 해결합니다.
   - **대체 페이지(올바른 canonical 포함)**: `result.html` 처럼 쿼리 파라미터로 늘어나는 페이지에서 정상적으로 나타납니다. 문제 없습니다.
   - **noindex 태그에 의해 제외됨**: 의도치 않게 막혔는지 해당 페이지 `<head>` 를 확인합니다.
   - **`robots.txt` 에 의해 차단됨**: `robots.txt` 가 실제 도메인으로 잘 바뀌었는지, 전체 허용 상태인지 확인합니다.

### 5-3. 색인 지연 대응

- 1~2주가 지나도 색인이 안 되면 **1-5(구글) / 2-5(네이버)** 의 색인 요청을 다시 합니다.
- 사이트맵 상태가 "성공"인지 다시 확인합니다. (도메인 치환이 누락되면 실패로 나옵니다.)
- 내부 링크를 보강합니다. 메인·케어가이드에서 각 상세 페이지로 가는 링크가 있으면 색인이 빨라집니다.
- 페이지 내용이 너무 적으면 색인이 늦어질 수 있으니, 4번 전략대로 본문을 충실히 채웁니다.

## 6. 구조화 데이터(JSON-LD) 점검

우리 페이지에는 검색 결과를 더 풍부하게 보여 주는 JSON-LD 구조화 데이터(HowTo·Article·Organization)가 들어 있습니다. 배포 후 한 번 검증해 주세요.

### 6-1. 리치 결과 테스트 도구로 검증

1. `https://search.google.com/test/rich-results` 에 접속합니다.
2. **[URL 테스트]** 탭에 점검할 실제 주소를 넣거나, **[코드 테스트]** 탭에 페이지 HTML을 붙여 넣습니다.
3. **[URL 테스트]** (또는 코드 검사)를 누르고 결과를 확인합니다.

### 6-2. 페이지별로 확인할 유형

| 페이지 | 기대 구조화 데이터 | 확인 포인트 |
|---|---|---|
| `/plants/*.html` (식물 상세) | **HowTo** (키우는 법 단계) + **Article** | 각 단계(step) 텍스트가 들어 있는지, `url`/`@id` 가 실제 도메인인지 |
| `/guide.html` 등 콘텐츠 페이지 | **Article** | 제목·작성/수정일이 채워졌는지 |
| 메인 등 사이트 공통 | **Organization** | 사이트 이름("우리집 초록친구"), 로고/URL 이 실제 도메인인지 |

### 6-3. 자주 나오는 문제와 대응

- **"항목을 감지할 수 없음"**: JSON-LD `<script type="application/ld+json">` 가 페이지에 실제로 들어 있는지 확인합니다.
- **URL이 `example.pages.dev` 로 나옴**: 0번 치환이 누락된 것입니다. 해당 페이지의 JSON-LD origin을 실제 도메인으로 고쳐 재배포합니다.
- **필수 속성 누락 경고(노란 표시)**: 리치 결과로는 노출되지만 권장 항목이 빠진 상태입니다. 가능하면 채워 주면 좋습니다.
- 검증을 통과했다면, 5-2의 색인이 끝난 뒤 Search Console **[개선사항]** 에서 HowTo/Article 인식 현황도 함께 확인할 수 있습니다.
