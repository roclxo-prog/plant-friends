# 우리집 초록친구 — v3 요구사항 정의서 (질문 7개 전부 필수 + 매칭 품질 강화)

> v2(필수 3 + 선택 4 + 분기)에서 **질문 7개 전부 필수**로 전환하고, **매칭 품질**을 측정 가능한 합격선으로 보장합니다.
> 대상: 50~60대 시니어. 정적 사이트(서버 0원)·가입 없음·URL 쿼리 무상태 원칙 유지.

## 0. 배경과 변경 요지

| 구분 | v2 (현재) | v3 (이번) |
|---|---|---|
| 필수 질문 | 3개(빛·물·목적) | **7개 전부** |
| 선택 질문 | 4개(장소·반려동물·크기·보는재미, 건너뛰기 가능) | (없음 — 선택 개념 폐지, 7개 모두 필수) |
| 분기 화면 | "이대로 추천받기 / 더 정확히 추천받기" | **제거** |
| 진행 표시 | "1/3" → 정밀화 시 7칸 확장 | **항상 "n / 7"** |
| 건너뛰기 보기 | "잘 모르겠어요/건너뛰기" | **제거**(모든 질문에 실제 답만) |

변경 이유:
1. 사용자 요청 — 7개 질문 전부 답하게 하여 매칭 입력을 완전하게 확보.
2. 매칭이 "선택과 다르게 이상함" 문제 → 모든 차원이 채워지면 점수식이 온전히 작동하고, 아래 품질 합격선으로 결과를 강제.

**7문항 순서**: ①빛 ②물 ③목적 ④장소 ⑤반려동물 ⑥크기 ⑦보는재미

## 1. User Story — 질문 7개 전부 필수

### US-1. 7개 질문에 하나씩 모두 답하고 결과로 진행하기

> **시니어 사용자로서**, 우리 집 환경을 빠짐없이 알려 주어 정말 잘 맞는 식물을 받기 위해, **빛·물·목적·장소·반려동물·크기·보는재미 7개 질문에 큰 버튼으로 하나씩 답하고**, 7개를 다 답해야 결과로 넘어가는 화면을 원합니다.

**Acceptance Criteria (검증 가능)**

- [ ] **AC-1.1 (7문항 순서·1화면 1질문)** 질문은 ①빛 ②물 ③목적 ④장소 ⑤반려동물 ⑥크기 ⑦보는재미 순서로, 한 화면에 정확히 1개씩만 나타난다.
- [ ] **AC-1.2 (분기 제거)** "이대로 추천받기 / 더 정확히 추천받기" 분기 화면이 **어디에도 나타나지 않는다**. 3번째 질문(목적)을 답하면 곧바로 4번째 질문(장소)으로 넘어간다.
- [ ] **AC-1.3 (건너뛰기 제거)** 어떤 질문에도 "잘 모르겠어요 / 건너뛰기 / 상관없어요" 보기가 없다. 모든 보기는 실제 답(값이 비어 있지 않음)이다.
- [ ] **AC-1.4 (미응답 시 다음 불가)** 현재 질문에 답을 고르지 않으면 다음 질문으로 진행할 수 없다. (보기를 누르는 것이 곧 다음으로의 진행 트리거이며, 답 없이 다음 화면이 뜨는 경로가 존재하지 않는다.)
- [ ] **AC-1.5 (7개 모두 답해야 결과)** 7번째 질문(보는재미)까지 답을 고른 뒤에만 `result.html`로 이동하며, 7개 답(`light·water·purpose·place·pet·size·interest`)이 **모두 URL 쿼리에 포함**된다. 하나라도 빠진 채 결과로 진입하는 경로가 없다.
- [ ] **AC-1.6 (← 이전으로 수정)** "← 이전" 버튼으로 직전 질문으로 돌아갈 수 있고, 돌아간 질문에서 이전에 고른 답이 선택 상태(`aria-pressed="true"`)로 복원되어 다시 고쳐 고를 수 있다. 첫 질문(빛)에서는 "← 이전"이 비활성(`disabled`)이다.
- [ ] **AC-1.7 (진행 표시 "n / 7")** 모든 질문 화면에 진행 상태가 **"n / 7"**(n=1~7) 형식으로 글씨로 표시된다(색만이 아니라 텍스트로). 진행바 칸 수는 항상 7칸이며 동적으로 확장/축소되지 않는다.
- [ ] **AC-1.8 (처음부터 다시)** "처음부터 다시" 버튼을 누르면 1번 질문(빛)으로 돌아가고 그동안 고른 답이 모두 비워진다.
- [ ] **AC-1.9 (무상태)** 답은 URL 쿼리스트링으로만 전달되며 localStorage·쿠키 등 영구 저장을 하지 않는다(개인정보 미저장 원칙 유지).

> 구현 참고(요구 아님): `scripts/quiz.js`에서 `REQUIRED`/`OPTIONAL` 분리와 `branch` 모드를 제거하고 7문항 단일 배열·단일 모드로 단순화. 각 문항의 "" 값 보기 삭제. `result.js`의 화이트리스트(`PET`·`SIZE`·`INTEREST` 등)는 그대로 유효.

## 2. User Story — 매칭 품질 보장 (측정 가능한 합격선)

### US-2. 내가 고른 답과 "어긋나지 않는" 상위 3종 받기

> **시니어 사용자로서**, 내가 고른 목적·반려동물·보는재미 등과 **어긋나지 않는** 식물 3종을 받기 위해, 답을 반영한 결과와 솔직한 안내를 원합니다.

아래는 `result.html` 상위 3종(이하 "결과 3종")에 대한 **합격/불합격을 자동 판정할 수 있는** 기준입니다. 7개 답이 모두 채워진 상태(US-1)를 전제로 합니다.

**Acceptance Criteria — 강제 규칙(반드시 충족, 위반 시 불합격)**

- [ ] **AC-2.1 (반려동물 안전 = 0 독성)** `pet=yes`이면 결과 3종에 `toxic_to_pets===true` 식물이 **단 한 종도 없다**(독성 노출 0). 안전종(현재 213종 중 120종)으로 항상 3종을 채울 수 있으므로 예외 없음.
- [ ] **AC-2.2 (텃밭=먹는 식물만)** `purpose=harvest`이면 결과 3종이 **모두** `tags_purpose`에 `"harvest"`를 포함한다(먹을 수 있는 식물만). harvest 태그 식물은 36종으로 3종 보장에 충분하다.
- [ ] **AC-2.3 (목적 만족)** harvest 외 목적(`air`·`deco`·`gift`)에서도 결과 3종 중 **최소 2종**이 사용자가 고른 `purpose`를 `tags_purpose`로 만족한다. 예: 공기정화(`air`) 선택 시 결과 2종 이상이 `air` 태그(air 식물 45종 보유). 3종 전부 만족이 가능하면 3종 전부 우선한다.
- [ ] **AC-2.4 (보는재미 반영)** 결과 3종 중 **최소 2종**이 사용자가 고른 `interest`(`flower`/`foliage`/`fruit`)를 `tags_interest`로 만족한다. 단 `pet=yes`로 안전 필터가 적용되어 해당 interest 안전종이 2종 미만인 경우, 가능한 최대치를 채우고 AC-2.6의 솔직 안내를 띄운다.

**Acceptance Criteria — 정렬·일관성**

- [ ] **AC-2.5 (입력 정합)** 결과 카드의 "왜 맞는지" 이유 문구가 실제 매칭된 차원과 **모순되지 않는다**(예: `interest=flower`로 뽑혔는데 "잎과 무늬가 멋져요" 이유가 나오지 않는다). 이유는 실제로 일치한 차원에서만 생성한다.
- [ ] **AC-2.6 (부족 시 솔직 안내)** 위 강제/품질 기준을 완전히 만족하는 후보가 3종 미만이라 보충(최소 3종 보장)이 필요한 경우, 결과 화면 상단에 **"딱 맞진 않지만 ~"** 류의 솔직한 안내 문구를 노출한다(예: "딱 맞진 않지만, 그중 가장 가까운 식물로 골랐어요"). 모든 차원이 0점인 폴백뿐 아니라 **목적/보는재미를 일부만 만족한 경우에도** 이 안내가 뜬다.
- [ ] **AC-2.7 (항상 정확히 3종)** 어떤 7개 답 조합에서도 결과는 **정확히 3종**이며 빈 결과·중복 식물·4종 이상이 발생하지 않는다.
- [ ] **AC-2.8 (점수 우선순위)** 정렬은 매칭 점수 내림차순 → 난이도 쉬운 순(매우 쉬움<쉬움<보통) → `common=true` 우선이며, 동일 점수에서 시니어가 키우기 어려운 종이 쉬운 종보다 위로 오지 않는다.

**측정/검증 방법(합격선 자동화)**

- [ ] **AC-2.9 (스윕 테스트)** 7개 차원 전 조합(또는 대표 ≥300개 무작위 조합)에 대해 `matchPlants`를 실행하는 회귀 테스트를 둔다. 합격선:
  - 모든 조합에서 결과 = 3종 (AC-2.7) → **100%**
  - `pet=yes` 조합에서 독성 식물 노출 → **0건** (AC-2.1)
  - `purpose=harvest` 조합에서 비-harvest 식물 노출 → **0건** (AC-2.2)
  - `purpose∈{air,deco,gift}` 조합에서 목적 일치 ≥2종 → **100%** (AC-2.3)
  - `interest` 지정 조합에서 보는재미 일치 ≥2종(안전 필터 예외 제외) → **95% 이상** (AC-2.4)
  - "딱 맞진 않지만" 안내 표시 여부가 위 보충 발생 조건과 **일치**(누락·오표시 0) (AC-2.6)

> 구현 참고(요구 아님): 현 `match.js`는 AC-2.1·2.2·2.7을 이미 보장. **AC-2.3(목적 ≥2종)·AC-2.4(보는재미 ≥2종)·AC-2.6(부분 만족 시 안내)** 강화를 위해 점수식만으로 부족한 경우 목적·보는재미 우선 채움 로직과 안내 트리거 조건을 추가해야 함. `purpose`의 점수 가중(현재 2)이 `place`(2)와 동률이므로, 목적 보장을 위해 채움 단계에서 목적 일치를 우선하도록 보강 권장.

## 3. 비기능 요구 — 시니어 UX (질문 7개로 늘어나도 유지)

질문이 3개에서 7개로 늘어도 아래를 **모두 유지**한다(이탈 방지).

- [ ] **NFR-3.1 (한 화면 1질문)** 항상 한 화면에 질문 1개·보기 버튼만 노출. 스크롤로 두 질문이 동시에 보이지 않는다.
- [ ] **NFR-3.2 (큰 버튼)** 보기·이동 버튼은 높이 48px 이상, 손가락 간격 넉넉, 본문 글씨 18px 이상.
- [ ] **NFR-3.3 (진행 표시 상시)** "n / 7" 진행 표시와 7칸 진행바가 모든 질문 화면에 보인다(지난 단계는 색 외에 ✓ 체크로도 구분).
- [ ] **NFR-3.4 (이전 가능)** "← 이전"으로 언제든 직전 질문 수정 가능(US-1 AC-1.6).
- [ ] **NFR-3.5 (짧은 문장)** 모든 질문·보기 문구는 한 줄·쉬운 말(어려운 한자어 없음). 질문 1문장, 보기 라벨은 짧은 명사구.
- [ ] **NFR-3.6 (접근성 유지)** 새 질문마다 제목으로 포커스 이동, `aria-current="step"`, `aria-pressed`, `prefers-reduced-motion` 처리 유지. **KWCAG 2.2 100% 충족** 유지, 명암 대비 4.5:1 이상.
- [ ] **NFR-3.7 (성능/비용)** Lighthouse 90+ 유지, 정적 사이트·서버 0원·`plants.json` 단일 데이터 유지.
- [ ] **NFR-3.8 (모바일 우선)** 모바일 세로 화면에서 7개 질문 내내 가로 스크롤 없이 모든 내용이 보인다.

## 5. Success Metrics

| 지표 | 정의 | 목표(예시) | 측정 |
|---|---|---|---|
| **추천 완료율** | 1번 질문(빛)을 본 사용자 중 7개 질문을 모두 답하고 결과를 본 비율 | **45% 이상**(3문항 60% 대비 하향 반영, 이탈 완화책으로 방어) | GA 이벤트: `quiz_start` → `quiz_complete` |
| **단계별 이탈율** | 질문 n→n+1 진행 시 이탈 비율(병목 질문 식별) | 단일 질문 이탈 **15% 이하** | GA 이벤트: `quiz_step`(n) |
| **결과 만족(목적 일치율)** | 결과 3종이 사용자가 고른 목적을 만족한 세션 비율(AC-2.2·2.3 충족) | **95% 이상** | 클라이언트 측정 이벤트 `result_purpose_match`(일치 종 수 기록) |
| **반려동물 안전율** | `pet=yes` 세션 중 결과에 독성 식물 0종인 비율 | **100%** | 이벤트 `result_pet_safe` |
| **쿠팡 클릭률(CTR)** | 결과·상세를 본 사용자 중 쿠팡 버튼 클릭 비율 | **8% 이상** | 이벤트 `coupang_click` |

> 측정 도구: 구글 애널리틱스 등 무료 분석 도구. 개인정보 저장 없이 이벤트 카운트만 집계.

## 6. 범위 밖 (Out of Scope)
